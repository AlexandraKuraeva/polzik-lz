# 1.01 — Уникальный email и хеши паролей: для Саши Кураевой

**Что поменялось:** у двух сотрудников больше не может быть одной почты (даже в разном регистре) — это
держит сама база. Пароли хранятся хешем, а не открытым текстом; старые пароли продолжают работать,
при первом входе сотрудника его пароль хешируется сам.
**Где:** вход, раздел «Сотрудники» → новый сотрудник; база — тестовый Docker-стенд с дампом.

## Шаги

- [ ] Тестовый стенд → загрузить дамп с открытыми паролями → у всех сотрудников пароль вида `$2…`, уникальный индекс по email есть
- [ ] Прогнать схему базы второй раз → без ошибок, ничего не меняется
- [ ] Вход → сотрудник из дампа своим старым паролем → входит; неверный пароль → «неверные данные»
- [ ] Вход → тот же email другими буквами (`Admin@LZ.media`) → входит
- [ ] База → вернуть одному сотруднику открытый пароль → он входит, в базе снова хеш
- [ ] «Сотрудники» → создать сотрудника → в базе хеш, в ответе формы пароля нет
- [ ] «Сотрудники» → тот же email в другом регистре → ошибка у поля «Email уже занят»
- [ ] База напрямую → вставить вторую строку с тем же email → ошибка уникальности
- [ ] Пустой стенд без индекса → вставить дубль и прогнать схему → ошибка со списком адресов-дублей
- [ ] Перезапуск сервиса при существующем админе → второго админа нет, ошибок в логе нет
- [ ] Линт и сборка → проходят

**Не баг:**
- Сменить или сбросить пароль из интерфейса нельзя — только запросом в базе (так и было).
- Вход по открытому паролю ещё остаётся — переходный путь, уберём отдельным планом после миграции всех баз.
- При ошибке в форме создания введённый пароль подставляется обратно в поле — это ввод админа, вынесено в техдолг.

Замечания: шаг · ожидал · получил · скриншот. Всё ок — «1.01 принято».

### Что проверить — Verification из ТЗ

Стенд: `docker compose -p polziks-test --env-file <env в scratchpad> up -d --build` с портами 3100/54400
(образец env — `.env.example` через `generate-env.mjs`), дамп — тот, что лежит в `scripts/` у проверяющего, если
есть, иначе созданные руками пользователи с открытыми паролями.

1. **Миграция на данных с открытыми паролями.** Загрузить дамп в `polziks-test`: `import-dump.sh` вызывает
   `docker compose` без флагов, поэтому проект и env задать окружением (`COMPOSE_PROJECT_NAME=polziks-test`,
   `COMPOSE_ENV_FILES=<env>`), либо вставить пользователей через `psql`. После — все `password` вида `$2…`,
   индекс `users_email_lower_key` есть. Второй прогон `polziks-schema.sql` — без ошибок, `UPDATE 0`.
2. **Вход.** Сотрудник из дампа входит своим старым паролем. Неверный пароль — «неверные данные». Email в
   другом регистре (`Admin@LZ.media`) — входит.
3. **Переходный вход.** Вручную вернуть одному пользователю открытый пароль, войти, проверить, что в базе снова
   хеш.
4. **Создание сотрудника.** Форма «Сотрудники» → новый сотрудник → в базе хеш, в ответе action нет `password`.
   Тот же email в другом регистре → ошибка поля «Email уже занят».
5. **Дубль в обход кода.** `insert` второй строки с тем же email в `psql` → ошибка `23505`.
6. **Дубль до индекса.** На пустом стенде удалить индекс, вставить дубль, прогнать схему → ошибка со списком
   адресов.
7. **Админ из `.env`.** Перезапуск сервиса при существующем админе — новой строки нет, ошибок в логе нет.
8. `npm run lint` и `npm run build` проходят.

Риск смотреть в коде: все места, где email попадает в запрос, нормализуют его одинаково; ни один `select`
пользователя, уходящий наружу, не включает `password`.
